# 识别精确度增强方案 — 五层纵深防御

> 日期：2026-09-24 ｜ 状态：设计评审中
> 关联文档：`2026-09-24-batch-extract-ledger-design.md`（总体设计）、`templates/_schema.md`（模板约定）

## 设计原则

1. **纵深防御**：错误在越早的层被拦截，修复成本越低；任何一层都无法独立保证 100%
2. **规则优先于模型**：能用确定性规则验证的（求和、正则、枚举），绝不依赖模型自觉
3. **无出处不采信**：提取字段必须能回溯到原文片段，否则视为幻觉
4. **闭环进化**：人工复核修正必须回流为评测数据，让精确度可度量、可持续提升

---

## 第 1 层：输入预处理（拦截"看不清"）

| 问题 | 手段 |
|---|---|
| 扫描件无文本层 | PyMuPDF 检测文本层；无文本层或文本密度 < 阈值 → 降级 OCR（PaddleOCR，PP-OCRv4） |
| OCR 质量差 | 图像预处理：纠偏（deskew）、去噪、对比度增强、DPI 归一化到 300 |
| 表格结构丢失 | 表格区域检测（PP-Structure）后走表格结构化解析，**不走纯 OCR 流水**——表格数字错一位就是金额错误 |
| 长文档截断 | 按章节/页分块提取后合并；关键字段（如金额）跨块出现时合并去重 |
| 印章遮挡文字 | 检测印章区域，OCR 时对红色通道做抑制处理 |

**质检信号**：OCR 置信度均值 < 0.85 → 整份文件置信度降级，字段全部进复核。

## 第 2 层：模型提取（拦截"提不准"）

1. **结构化输出约束**：走 NewAPI 网关 OpenAI 兼容接口，用 `response_format: json_schema`（不支持时降级 prompt 内 JSON 模板 + 输出解析重试，最多 2 次）。**字段枚举直接写进 schema**，模型无法输出枚举外的值。
2. **模板即提示词**：`templates/*.yaml` 的 `hint` 字段逐条注入（发票号码 8/20 位、大小写金额冲突以小写为准等边界规则），把踩过的坑固化进提示词。
3. **少样本示例**：每个模板维护 1-2 个黄金示例（输入片段 → 期望 JSON），放 prompt 消化不掉的进 few-shot。
4. **推理配置**：`temperature=0`；票据/表单类优先走**视觉模型直接读图**（qwen-vl 等），避免 OCR 误差传递；长合同走长文本模型全文提取。
5. **分而治之**：单次提取字段数 > 20 时拆多次调用（如合同分"基本信息/付款条款/违约条款"三轮），单轮字段越少准确率越高。
6. **自一致性采样（可选开关）**：关键字段（金额、日期）采样 3 次投票，不一致即降置信度——成本换精度，仅对 `required: true` 且 `type in (money, date)` 的字段启用。

## 第 3 层：溯源回验（拦截"编造"）★ 本方案最关键的一层

每个字段要求模型同时输出 `value` + `evidence`（原文片段 + 页码），提取完成后程序自动回验：

```python
def grounding_check(field, source_pages):
    quote = field.evidence
    best = max(
        (fuzz.partial_ratio(normalize(quote), normalize(page.text), score_cutoff=85), page.no)
        for page in source_pages
    )
    if best.score < 85:
        return verdict = FAIL        # 原文里找不到出处 → 直接判幻觉，置信度归零进复核
    field.page = best.page
    return verdict = PASS
```

- 归一化：去空白/全半角/大小写后再比对（RapidFuzz `partial_ratio`）
- **三态判定**：evidence 找得到 → 采信；找不到 → 置信度 ×0.3 强制进复核；模型没输出 evidence → 视为 FAIL
- 回验结果写入溯源 sheet，复核人员点击即可核对——**溯源从"承诺"变成"已验证"**

## 第 4 层：规则校验（拦截"算错/格式错"）

已有 `rule`（正则）、`sum_check`（求和）、`cross_checks`（勾稽）、`enum` 校验，补充：

1. **格式归一化校验**：日期统一 `YYYY-MM-DD`（非法日期如 2 月 30 日 → 拦截）；金额去千分位/全角数字后转 float（转换失败 → 拦截）
2. **业务勾稽库**（模板 cross_checks 之外的平台级规则）：发票三勾稽、合同"付款节点求和≈总额"、报价"数量×单价≈小计"
3. **跨文档核对（批量场景独有优势）**：同一批次的报销单 ↔ 附件发票逐张核对（金额/税号/日期匹配），银行回单 ↔ 合同付款节点核对；**不匹配的成对标红**——单据看单据，比看单据本身更可靠
4. **枚举越界**：模型输出 enum 外的值 → 保留原值 + 标黄（不直接丢，可能模板枚举不全）

## 第 5 层：分级路由（拦截"剩余不确定性"）

**置信度合成公式**（字段级）：

```
conf = model_conf                      # 模型自报
     × grounding(1.0 | 0.3 | 0.5)      # 回验三态
     × rules(1.0 | 0.5)                # 规则通过 | 失败
     × vote(1.0 | 0.7)                 # 自一致性一致 | 不一致
```

| conf | 路由 | 台账表现 |
|---|---|---|
| ≥ threshold（默认 0.8） | 直接入库 | 正常 |
| 0.5 ~ threshold | 人工复核队列 | 单元格标黄 |
| < 0.5 或 required 缺失 | 复核 + 整行标红 | 状态列"待复核/失败" |

- 复核界面只展示**低置信字段 + 其原文出处**，人只看有疑问的地方，不全文核对
- **复核修正回流**：所有人工修改记录 (文件 hash, 字段, 模型值, 人工值) 落库 → 攒成金标数据集

## 闭环：度量与迭代

1. **金标数据集**：每模板从复核修正中沉淀 ≥ 30 份标注样本（初期人工标）
2. **回归评测**：模板/提示词/模型任何变更，跑一遍金标集，输出**字段级 precision/recall**（按字段类型分组），指标下降则禁止发布——精确度从"感觉"变成"看板"
3. **复核率看板**：核心指标不是准确率，而是**自动通过率**（目标：票据类 ≥ 90%，合同类 ≥ 75%）与复核工时趋势
4. **badcase 机制**：`failed/` 与复核修正自动归档，每周聚类 top 错误模式 → 转成新的 `hint`/`rule` 固化进模板

## 实施优先级

| 阶段 | 内容 | 理由 |
|---|---|---|
| A（随 P1） | 结构化输出 + hint 注入 + grounding 回验 + 格式归一化 | 投入小、收益最大，防幻觉是底线 |
| B（随 P2） | sum_check/cross_checks 全量启用 + 置信度合成与分级路由 | 批量场景开始有用 |
| C（随 P3） | 跨文档核对 + 自一致性采样 + 复核修正回流 | 精确度闭环成形 |
| D（随 P4） | 金标回归评测 + 通过率看板 | 可持续迭代的基础设施 |
