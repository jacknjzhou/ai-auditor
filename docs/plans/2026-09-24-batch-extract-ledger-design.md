# 批量文件模板提取 + 台账汇总 — 设计文档

> 日期：2026-09-24 ｜ 状态：设计评审中
> 背景：已有"单文件按模板 LLM 提取"能力，本设计将其升级为"本地文件夹定时批量处理 → 自动匹配模板 → 分模板输出台账 Excel"。

## 1. 目标

- 监控本地文件夹，**定时自动**批量提取文件中的关键信息
- 一批文件可混合多种文档类型，**每个模板单独输出一张台账**
- 字段级精确度保障：溯源、置信度、规则校验、失败隔离重跑

## 2. 整体流程

```
inbox/ 文件 → 类型识别+模板匹配 → 异步逐文件提取 → 字段校验 → 分模板汇总 → 台账 Excel
```

1. **批量输入**：用户把文件丢进监控目录（可按业务建子目录）
2. **模板自动匹配**：规则（关键词/文件名 pattern）优先，命中多个取最高分；无法确定 → `failed/`，可人工指定模板重跑
3. **逐文件提取**：队列并行，单文件失败不阻塞整批；每字段附原文出处（页码+片段）
4. **字段级校验**：规则兜底（求和/日期/正则/必填）+ 置信度分级
5. **汇总输出**：按模板分组各生成一份 `台账_<模板名>_<日期>.xlsx`

## 3. 目录协议与调度

```
D:\office_watch\
├── inbox/                    # 用户投递
├── processing/               # 原子移动，防重复处理
├── done/<日期>/              # 完成归档
└── failed/<日期>/            # 失败文件 + 同名 .error.json（含原因/可指定模板重跑）
```

- **调度**：Windows Task Scheduler（或办公平台定时任务）触发 CLI：
  `office_extract run --watch-dir D:\office_watch`
- **重复文档检测与提示**：见下方 §3.1
- **未匹配模板**：进 `failed/`，错误原因"未匹配模板"，支持人工指定模板后重跑

### 3.1 重复文档检测与提示（三层）

重复发生在两个环节：**提取前**（文件级）和**提取后**（业务实体级），检测到即提示，不再静默跳过。

| 层级 | 检测时机 | 判定依据 | 处理动作 |
|---|---|---|---|
| **L1 文件精确重复** | 入 inbox 扫描时 | 内容 hash 与 `done/` 及本批已处理文件相同 | 跳过提取 + **重复提示**（默认），可配置 `on_duplicate: skip\|alert\|reprocess` |
| **L2 业务键重复（内容一致）** | 字段提取完成后 | 模板 `dedup_keys`（发票号码/合同编号）跨批次撞库，且关键字段值一致 | 正常入库但标记 `duplicate`，台账"状态"列显示"🔁 重复"，批次结束推送提示 |
| **L3 业务键重复（内容冲突）** | 同上 | 同业务键但金额/日期等关键字段**不一致** | 标红 + urgent 级推送（危险信号：可能重复报销/阴阳合同） |

**提示出口**：

1. **批次报告**：每批跑完输出 `重复文件清单` sheet（`文件名 | 重复类型 | 与哪份文件重复 | 原处理日期`），L1/L2/L3 都进这张表
2. **实时推送**：L3（内容冲突）批次结束即推钉钉/企微；L1/L2 默认仅进批次报告，可配置升级为推送
3. **预警兜底**：`office_alert check` 每日任务复扫 L2/L3，防批次推送遗漏

**配置示例**（模板级 + 全局级）：

```yaml
# 全局（config.yaml）
dedup:
  file_hash: alert            # skip | alert | reprocess，默认 alert
  bizkey_conflict_push: true  # L3 是否实时推送

# 模板级（vat_invoice.yaml）
dedup:
  keys: [invoice_number]      # 业务键，撞库范围跨批次
  compare_fields: [amount, invoice_date, seller_tax_id]   # L3 冲突判定字段
```

## 4. 模板 Schema（YAML/JSON）

> **已细化落地：全部 13 个模板定义见 `templates/` 目录**（schema 约定见 `templates/_schema.md`），可直接作为 P1 配置加载。

```yaml
template_id: contract_v1
name: 采购合同要素
match:
  keywords: ["合同", "甲方", "乙方", "采购"]
  filename_patterns: ["*采购合同*", "*contract*"]
fields:
  - key: party_a
    label: 甲方名称
    type: string          # string | money | date | number | enum
    required: true
  - key: amount
    label: 合同金额（元）
    type: money
    required: true
    sum_check: true       # 可选：与附件明细求和核对
  - key: sign_date
    label: 签订日期
    type: date
options:
  confidence_threshold: 0.8   # 低于此值标黄
```

## 5. 台账 Excel 结构（每模板一份）

- **主表**：一行一个文件；列 = 模板字段 + 固定 `文件名 / 状态 / 最低置信度` 三列；money/date 写真实单元格类型，支持筛选求和
- **溯源 sheet**：`文件名 | 字段 | 提取值 | 原文片段 | 页码` — 点不出处的数据不可信
- **重复清单 sheet**：`文件名 | 重复类型(L1/L2/L3) | 重复对象 | 原处理日期`，每次批次必出
- **标注**：低置信度单元格标黄（⚠️ 待复核）、失败行标红、L2 重复行"🔁 重复"、L3 内容冲突整行标红

## 7. 精确度保障闭环

> **已深化为独立文档：`2026-09-24-accuracy-enhancement-design.md`（五层纵深防御 + 复核回流评测闭环）**，本节为摘要。

1. **字段级溯源**：每字段附原文出处（页码/片段），写入溯源 sheet
2. **规则兜底优先**：金额求和、日期格式、正则、必填检测——规则能查的不靠模型
3. **置信度分级**：低于阈值（默认 0.8）标黄进复核清单；台账里附"最低置信度项"列
4. **双模型交叉校验（可选开关）**：两个模型各自提取，不一致字段标黄
5. **失败隔离**：单文件失败不阻塞整批；`failed/` + `.error.json` 支持人工介入后重跑

## 8. 技术选型建议

- **语言**：Python CLI（与现有提取实现同栈）
- **解析**：PDF → PyMuPDF（文本层），扫描件降级 PaddleOCR；Word → python-docx；Excel → openpyxl；台账输出 → openpyxl
- **LLM**：走 NewAPI 网关（OpenAI 兼容 `/v1/chat/completions`），便于换模型与双模型校验
- **调度**：Windows Task Scheduler / 平台定时任务
- **后续演进**：CLI 跑通后，同一套模板 Schema 与提取核心可挂到 FastAPI 办公平台，补 Web 上传与在线台账界面
